# FE Algorithm Gym 设计方案

日期：2026-07-15  
状态：已完成产品设计确认，待用户审阅文档

## 1. 背景与目标

将现有 `Junaspark/fe-algorithm-notes` 从静态训练手册升级为个人专用的前端面试刷题系统。系统每天安排训练、支持桌面和手机完整编码、即时运行测试、记录错误与进步，并由可替换的模型 Agent 生成长期复盘和后续训练建议。首版使用 Codex，但业务数据与工作流不得依赖 Codex 专有格式。

现有仓库包含 19 道已练习题，覆盖数组、函数工具、对象、设计模式、Promise、定时器、数据结构和 Event Loop。迁移时必须保留每题代码、复杂度、易错点、状态和面试追问。

## 2. 成功标准

1. 每天 09:30（Asia/Shanghai）提供两道 JavaScript 题：一道数据结构/算法题和一道前端手写题，预计总用时 45–60 分钟。
2. 用户可在桌面或手机完成读题、编码、运行测试、提交和查看反馈的完整流程。
3. GitHub OAuth 登录后只允许 GitHub 用户名 `Junaspark` 访问训练数据。
4. 草稿、提交、错题和能力画像在手机与电脑间同步。
5. 网页即时提供测试结果与规则化反馈；首版由 Codex 在不使用独立 OpenAI API Key 的前提下生成深度复盘。
6. 当天两题完成后，题库、最终代码和学习报告自动提交到 GitHub `main`。
7. 未完成任务会跨日保留并继续提醒，不生成新题。

## 3. 已确认的产品决策

- 产品范围：个人专用，不开放注册。
- 登录方式：GitHub OAuth，仅放行 `Junaspark`。
- 默认语言：JavaScript。
- 每日训练量：标准模式，两题、45–60 分钟。
- 题型组合：一道数据结构/算法题加一道前端手写题。
- 桌面布局：专注分栏，左侧题目、右侧编辑器、底部测试结果。
- 手机布局：题目、代码、测试/反馈标签页；手机可完整编码、运行和提交。
- Agent 策略：首版不配置模型 API Key，不尝试复用 ChatGPT/Codex 订阅作为自建网站 API 凭证；通过通用 Agent 适配层调用 Codex，后续允许替换或并行接入其他模型 Agent。
- GitHub 策略：每日训练完成后直接提交到 `main`，不创建 Pull Request。
- 迁移策略：直接升级现有仓库并迁移全部 19 道旧题。

## 4. 总体架构

采用轻量全栈 PWA：

1. **训练 PWA**：响应式刷题界面、可安装到手机桌面、离线草稿、JavaScript 编辑器和浏览器判题。
2. **应用服务**：GitHub OAuth、账号白名单、题目 API、训练计划 API、提交 API、GitHub 同步任务。
3. **训练数据库**：保存实时题库、每日计划、草稿、提交、复盘、能力画像和同步状态。
4. **浏览器执行沙箱**：在 Web Worker 中执行用户代码和测试，限制运行时间，捕获同步错误、异步拒绝和超时。
5. **Agent 编排器**：通过稳定的输入输出协议创建选题或复盘任务，处理幂等、重试、超时和结果校验，不包含具体模型调用逻辑。
6. **Agent 适配器**：首版提供 Codex 适配器；后续可增加其他云端模型、本地模型或外部 Agent 适配器，而不修改训练领域逻辑。
7. **GitHub 仓库**：保存可读、可追溯的题目定义、通过后的最终代码、错误总结与周报。

数据库是应用实时状态的权威来源，GitHub 是版本化训练成果与可维护题库的权威副本。草稿和会话数据不写入 GitHub。Agent 只通过版本化 JSON Schema 读取任务上下文和写回结果，不直接读写数据库表或 GitHub 仓库。

### 4.1 Agent 中立协议

编排器向所有 Agent 提供统一任务信封：

- `jobId`、`jobType`、`schemaVersion` 和幂等键；
- 脱敏后的用户能力画像、题目、提交代码、测试证据和历史错误；
- 明确的输出语言、评价维度、长度限制和结构化结果 Schema；
- 超时、重试次数和允许使用的工具范围。

Agent 返回统一结果：状态、结构化选题或复盘、置信度、警告、提供方标识、模型标识、提示词版本、开始/完成时间和可审计摘要。应用只消费经过 Schema 校验的结果。

适配器接口至少提供 `dispatch(job)`、`getResult(jobId)` 和 `healthCheck()`。具体认证、任务投递、轮询或回调方式封装在适配器内部；编排器不得假设结果会同步返回。

首版 Codex 适配器采用异步任务桥：应用持久化标准 `AgentJob`，Codex 定时任务通过授权连接读取待处理任务并写回标准结果。它不把 ChatGPT/Codex 订阅当作 API 使用。未来具备正式 API 的模型适配器可以在内部直接请求提供方，但对编排器仍表现为相同的异步协议。

## 5. 核心用户流程

### 5.1 任务生成与提醒

1. 每天 09:30 检查是否存在未完成计划。
2. 若存在未完成计划，推送原计划，不生成新题；若只剩一题，提醒内容仅包含剩余题目。
3. 若没有未完成计划，根据能力画像生成当天两题。
4. 当天 20:00 再次检查；仍未完成时发送一次提醒。
5. 两题完成后，下一次 09:30 才生成新计划。
6. 连续训练天数按完成计划计算，跨日重复提醒不增加天数。

手机通知优先使用 ChatGPT/Codex 账户可用的 Push 渠道，邮件作为可用时的兜底。项目级本地任务依赖电脑开机和桌面应用运行；网页级提醒不应依赖本地文件。

### 5.2 刷题与提交

1. 用户从提醒链接进入今日训练页。
2. 编辑器自动保存草稿；断网时保存到本机，联网后同步。
3. “运行代码”执行公开测试并展示日志、断言差异、错误栈和耗时。
4. “提交”执行完整测试并保存提交证据；全部测试通过后才能标记完成。
5. 页面立即显示规则化反馈，包括测试通过率、典型边界条件、复杂度自评检查和代码结构提示。
6. Agent 编排器创建结构化复盘任务；首版 Codex 适配器补充思路、复杂度、可读性、面试表达、替代方案和复训建议。

### 5.3 GitHub 同步

当日两题全部完成后创建 `GitSyncJob`，仅导出：

- 题目定义与可公开测试；
- 通过后的最终代码；
- 错误总结、复杂度、知识点和面试追问；
- 每周学习报告。

不导出未完成草稿、OAuth 信息、会话数据、令牌或私密配置。自动同步只允许写入 `exercises/`、`solutions/` 和 `reports/`。提交信息使用 `practice: complete YYYY-MM-DD daily exercises` 格式。

## 6. 页面与组件

- **今日训练**：两题卡片、完成进度、预计用时、连续天数和继续训练入口。
- **刷题工作台**：题目说明、代码编辑器、测试面板、提交按钮、反馈区和自动保存状态。
- **题库**：按类型、难度、状态、知识点和薄弱点筛选。
- **错题本**：失败提交、错误原因、正确方案、下次复训日期。
- **成长报告**：周趋势、题型掌握度、平均用时、一次通过率和面试准备建议。
- **同步状态**：显示数据库保存、离线草稿、Agent 复盘和 GitHub 提交状态。

## 7. 数据模型

### Exercise

包含题干、题型、难度、知识点、函数签名、模板代码、公开测试、隐藏测试、参考复杂度和面试追问。

### DailyPlan

包含训练日期、算法题、前端手写题、推荐原因、各题状态、创建时间和完成时间。同一时刻最多存在一个未完成计划。

### Draft

包含题目、用户、代码、设备标识、版本号和保存时间。服务端采用乐观并发控制；发生跨设备覆盖时保留最近版本供恢复。

### Submission

包含最终代码、测试结果、执行耗时、尝试次数、训练用时、复杂度自评和提交时间。

### Review

包含规则反馈、Agent 深度复盘、薄弱点标签、掌握度变化、下次复训时间，以及提供方、模型、适配器版本、提示词版本和结果 Schema 版本。

### AgentJob

包含任务类型、版本化输入、目标适配器、幂等键、状态、尝试次数、超时、结构化输出、校验错误和审计元数据。训练领域对象只引用已成功校验的 `AgentJob` 结果。

### GitSyncJob

包含导出清单、目标路径、远端基准 SHA、重试次数、最近错误和同步状态。

## 8. 选题策略

1. 每日固定保持算法题与前端手写题各一题。
2. 优先选择到期错题和历史出现边界条件错误的知识点。
3. 同一知识点避免连续两天机械重复。
4. 连续通过后逐步提升难度；多次失败后拆成基础题或关联复训题。
5. 每周至少安排一次限时面试模式。
6. 初始画像优先关注 Promise 边界条件、`deepClone`、`this`、定时器和 Event Loop。

## 9. 安全与异常处理

- OAuth 回调在服务端交换令牌，并再次校验 GitHub 用户名；非 `Junaspark` 返回无权限页面。
- OAuth 密钥、会话密钥、GitHub 写入令牌和未来的模型提供方凭证只能存放在服务端密钥管理中，不进入 Agent 任务上下文。
- 用户代码在独立 Web Worker 中执行；超时后终止 Worker，避免死循环阻塞页面。
- 服务端不直接执行任意用户 JavaScript，只保存代码与客户端测试证据。
- 草稿离线写入本地队列；恢复联网后按版本同步，冲突版本不静默丢弃。
- GitHub 同步前读取远端最新 SHA 并校验导出 Schema；远端变化或校验失败时停止提交，保留任务等待重试，不强制覆盖。
- GitHub 自动化不得修改应用源码、工作流、环境配置或同步白名单外目录。
- 当前 Agent 选题失败时使用预设复训队列；复盘失败进入可重试队列，也可以切换到另一已配置适配器。通知失败不影响今日训练页可用性。
- Agent 输出必须通过大小限制、Schema 校验和允许字段过滤；未经校验的文本不能直接改变掌握度、题库或 GitHub 同步内容。

## 10. 测试与验收

### 自动测试

- 题目和测试用例 Schema 校验。
- 选题约束、未完成计划复用、09:30 与 20:00 提醒规则的单元测试。
- OAuth 用户白名单、未授权访问和会话过期测试。
- Worker 正常执行、语法错误、同步异常、Promise 拒绝、死循环和超时测试。
- 草稿自动保存、离线队列、跨设备版本冲突与恢复测试。
- GitHub 导出路径白名单、远端 SHA 冲突、重试和提交内容快照测试。
- Agent 适配器契约测试：相同输入信封、统一输出 Schema、幂等行为、超时、无效结果、重试和降级。
- 使用模拟适配器验证训练流程不依赖 Codex；切换适配器不得修改题库、提交或能力画像的数据结构。
- 桌面与移动端核心流程的端到端测试。

### 验收场景

1. `Junaspark` 可登录，其他 GitHub 用户无法进入训练数据。
2. 桌面和手机均可完成读题、编辑、运行、提交和查看反馈。
3. 刷新或更换设备后能恢复草稿与训练状态。
4. 任意代码死循环或异步超时不会使页面失去响应。
5. 未完成计划在次日 09:30 原样推送，20:00 再提醒，且不生成新题。
6. 两题完成后，白名单目录内容自动提交到 GitHub `main`。
7. 19 道旧题及其总结、错误与追问完整迁移。
8. 禁用 Codex 适配器并启用模拟适配器后，任务生成、提交、复盘入库和页面展示流程仍可运行。

## 11. 首版范围外

- 多用户注册、排行榜和社区题解。
- 自建网站内的实时大模型 API 点评，以及非 Codex 模型适配器的实际接入；首版仅实现通用接口和 Codex 适配器。
- TypeScript 或多语言运行环境。
- 服务端执行不受信任代码。
- 自动修改应用源码或自动合并非训练数据变更。

## 12. 实施阶段建议

按风险和价值拆成连续阶段：项目与数据基线、认证和数据层、刷题工作台与判题、移动 PWA 与同步、每日计划与通知、GitHub 自动提交、Agent 中立协议与 Codex 适配器、完整迁移与验收。详细任务拆分在本设计文档审阅通过后另行编写。
